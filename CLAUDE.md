# sky130-sram-compiler — agent instructions

Open-source canary block: an SRAM compiler on SkyWater sky130, built on a
logic-rule 6T bitcell, designed and verified by AI agents. **Mixed-signal** —
analog bitcell and periphery plus synthesized control logic — so both flows
apply.

- **PDK**: SkyWater sky130 (open PDK). Analog: xschem + ngspice. Digital:
  cocotb + Icarus, Yosys, OpenROAD. Layout, DRC, LVS and view generation
  through klayout-tools (`klt`).
- **Marker-layer rule switching is the point, and the risk.** The bitcell
  is drawn to logic rules; the foundry SRAM cells are drawn to relaxed rules
  legal only inside the SRAM core-area marker. Establish first exactly how
  klt's sky130 deck handles that marker — inside, outside and at the edge —
  and test it with both cells. A deck that silently applies the wrong rule
  set is the most important finding this repo can produce.
- **A compiler proves a family, not an instance.** Every size the compiler
  accepts must be generated by the same code path, and the reference
  instances are DRC/LVS-clean before any range is claimed. Pitch-matched
  periphery is where the generator will break; expect it.
- **This block is not competing with OpenRAM.** Use OpenRAM's sky130 output
  as a reference and comparison, cite it when you do, and do not reimplement
  it. If the honest conclusion of some piece of work is "OpenRAM already
  does this correctly," record that — it is a real result.
- **Scope discipline.** No `consumes:` edge is declared. The margin
  definitions, corner and Monte Carlo methodology and sim harness come from
  `gf180-sram`, which is master for them: take them by pinned reference
  (`reuse.lock.json`, `REUSE.md` in `2AMLogic/2am`), do not redesign them.
  The device-level design is new here. A finding about `gf180-sram` is filed
  on `gf180-sram`.
- **Friction protocol (the canary's job)**: every time klayout-tools is
  awkward, missing a capability, or wrong for what you need, file an issue at
  `2AMLogic/klayout-tools` describing the tool gap generically — that tracker
  is scoped to the tool, so keep design-specific detail out of it and describe
  the gap, not the design.
- **Verification is the product**: no claim without a testbench. PVT corners
  on every recorded analog result; stability margins also need Monte Carlo
  evidence; recorded results are append-only evidence.
- Spec changes go through `spec/` with a decision record; agents do not relax
  the ratified spec to make results pass.
- **The 256 × 32 instance through the compiler path closes first.** The
  other reference instances follow; range growth and 1RW1R wait.
